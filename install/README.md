# Installation defaults

This tree contains package lists and system, hardware and user setup steps. `omarchy-base.packages` supplies the shared default apps, including Grok Bot; architecture-specific lists add or exclude packages where needed. The existing Omarchy installer and package helpers consume these lists.

`config/os-branding.sh` applies the Ve OS system display name through `omarchy apply os-branding`. It creates a local `/etc/os-release` override, keeping the base distribution ID, version and support URLs unchanged; the package-owned `/usr/lib/os-release` is never rewritten. Repeat runs do nothing when the override is current. Each changed run saves the original file or symlink and its contents under the printed `/var/backups/ve-os-branding-*` directory. To roll back, remove `/etc/os-release` and copy that backup's `os-release` with `cp -a` (or leave the override absent if the backup contains `os-release.absent`).

The repository supplies Ve OS session, boot-menu, splash and first-boot setup assets. An installer ISO built elsewhere must vendor these updated assets separately. Existing firmware entries named `Omarchy` remain compatible; newly created Direct Boot entries use `Ve OS`. Setup defaults new hostnames to `ve-os`; refreshes never rename an existing machine.

The same command publishes the Ve font to the existing package font location and the `ve` notification icon, then selectively changes inherited product labels in installed session, fastfetch, Limine and service files. Custom options and unrelated files are preserved. Changed resources are backed up with their relative paths under the printed `/var/backups/ve-os-assets-*` directory; restore individual saved entries with `cp -a`, removing their destination first to restore symlinks correctly. A `.absent` marker means the destination was newly created. The font cache and system service metadata are refreshed; restart the desktop shell and reload user service metadata after applying. Login/splash publication still uses `omarchy refresh sddm` and `omarchy refresh plymouth`, which own their existing backup and initramfs update steps.
